# README

GitHub repository for the paper:

**"A 4200-hour HyperFlash and ÉCLAT campaign on the hyperactive FRB 20240114A: constraining energetics with the most brilliant bursts"**
This repository contains the scripts and databases used to generate the plots and results presented in [Ould-Boukattine+2026](https://arxiv.org/abs/2605.18513).
The data are hosted on Zenodo and can be retrieved [here](https://doi.org/10.5281/zenodo.20185181).

## Software

The pipeline used to process and search the baseband/VDIF data can be found at [frb-baseband](https://github.com/pharaofranz/frb-baseband). The software used to transfer the radio data can be found at [jive5ab](https://github.com/jive-vlbi/jive5ab).
The burst searcher software is [Heimdall](https://sourceforge.net/projects/heimdall-astro/). The burst classifier software [FETCH](https://github.com/devanshkv/fetch) can be found here. The pulsar processing package [DSPSR](https://sourceforge.net/projects/dspsr/) is hosted here, and [SIGPROC](https://github.com/SixByNine/sigproc) can be retrieved here.

## Files

### `frb.yml`

YAML file used to reproduce the Python environment for the analysis.

### Bash scripts (`.sh`)

Scripts used to generate and prepare filterbank files and archive files used in the analysis.

## Folders

### `./2bit-analysis-retriever`

Code used to retrieve the 2-bit data products hosted in our AstroFlash archive.

### `./atels_analysis`

Code and plotting files used to create the plots for the ATels released for this FRB repeater.

### `./cand_detection_plots`

FETCH candidate-burst plots.

### `./confs` & `./confs_2`

Configuration files for the various bursts. These configuration files are used as input to the `frb-baseband` pipeline.

### `./databases`

- `FRB20240114A_HyperFlash_paper_table_v2.csv`: Table containing the burst properties for the HyperFlash-detected bursts (Table XXXX).
- `fast_zhang_2025`: CSV file containing the burst properties of the 11,000 bursts from FAST, together with an additional CSV file in which the saturated bursts are labelled.
- `NRT_burst_properties.csv`: NRT/ÉCLAT burst properties at L-band.
- Various other CSV files containing data for individual telescopes.

### `./dm_opt_loop`

Code, scripts, and plots used to optimise the DM with SFXC in a coherent way.

### `./flags`

Files containing the channels to be flagged for each burst. This flagging was used in the computation of the fluences.

### `./helper_scripts`

Various highly specialised helper scripts for niche tasks.

### `./observing_hours`

CSV files containing the exposures towards this FRB.

The CSV file containing all exposures used to calculate the total observing time is:

`./databases/r147_fullcampaign_V3.csv`

Additionally, there are daily exposure times per telescope, as well as the unique exposures.

There is also the niche code used to calculate the exposure times and routines for the Dwingeloo telescope.

The underlying master dataframe containing all observations is not publicly available. If you wish to receive this, please contact the AstroFlash team.

### `./plots`

All plots from the paper, as well as additional plots, saved as `.png` and `.pdf` files.

Also stored here are the diagnostic plots generated by the analysis pipeline for each burst, saved as PDFs showing the on-burst time series and ACF results.

### `./python`

Various Python scripts, including the burst-distribution code, delta-DM significance code, waterfall code, and the STROOP example.

### `./spc`

Bash commands used to execute the scattered power correction (SPC) in the analysis workflow.

### `./the_stroop_p55097`

Waterfall code used to open the STROOP bursts. The accompanying filterbank file is hosted on Zenodo.

### `./vbs_data`

Example of the mounted VBS data structure.

Due to the large file sizes, the raw voltage data are not all hosted on Zenodo. If you wish to work with the raw voltage data, please contact a member of the AstroFlash team to obtain access.

This directory provides an example of how the pipeline works with the mounted files and how the data are structured.

### `./vex`

Scheduling `.vex` files generated by pySCHED.

These `.vex` files are essential for decoding the raw voltage data burst snippets. Without the corresponding `.vex` files, the VDIF data are not usable.
